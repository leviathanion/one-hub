# 支付 V2.2 停机升级签收

本文记录支付内核和兑换数据共同上线的前置条件。代码测试通过不代表历史资金数据已签收。本文不包含真实部署数据；由部署负责人填写结果后恢复服务。

实现契约见[支付订单架构](/dev/payment-order-architecture)。四类网关、支付宝三个产品、订单 API 和前端在同一次停机更新中发布，不运行新旧资金 writer。

## 停机前

1. 记录部署版本、数据库引擎、备份位置、启用的网关及产品。
2. 对每个实际商户确认通知的失败应答、重投间隔和最短保留期限。没有可靠重投保证的网关先停新单并排空待付款责任；无法排空时保持该网关禁用，明确旧单处理入口。
3. 停止创建订单、支付回调和 API/Telegram 兑换入口，等已有操作完成后退出旧进程，再取得一致数据快照。

## 数据结果签收

空库须核实没有历史订单和兑换事实，并验证最终结构。已有数据先由单个主实例执行启动迁移；能够从原记录无损推导的内容自动转换，无法确定的事实会报告表名或记录 ID 并阻止启动。下表仍需核对；新增列默认值不是历史事实。

### 启动自动迁移范围

- 订单的十进制 `order_amount` 根据自身币种无损转换成 `expected_amount_minor`，`gateway_no` 转为真实交易引用；空交易引用转为 NULL。已有新值不一致、金额超出整数范围或带有不能表示的小数时停止。查询观察元数据允许由 AutoMigrate 增加。
- 旧 Suno/Kling 任务中，已完成的结算快照按原归属和额度核对后转入统一 owner；更早格式的成功记录保留原最终额度，失败或取消记录仅在额度为零时自动转换。旧在途任务、未完成的结算快照、缺少退款证据的非零失败记录须先核查。整个转换不改用户、Token 或渠道额度。
- 旧 `midjourneys` 的上述明确终态记录自动导入 `tasks`，保留上游任务 ID、用户、渠道、提示词、图片和毫秒时间字段。统一表分配新的本地记录 ID；确定性的 owner 标识保证重跑不重复导入。最后的清理迁移 `202609090009` 再次逐条核对目标记录，全部通过后删除旧表；已完成上一版导入的部署也会执行该清理。歧义记录、身份冲突、目标内容不一致或尚未迁移的额外旧列会保留旧表并停止启动。
- `prices` 中所有列都相同的重复记录自动合并，再建立唯一索引；内容不同、规范化后名称冲突的价格仍须核对。
- Token limits 的旧结构迁移遇到错误不再标记成功；已被旧迁移跳过的记录由补充迁移再次处理。
- 启动迁移末尾删除废弃的 `abilities` 路由派生表和 `responses_ws_settlement_intents` 表。其他表不会因未出现在当前 AutoMigrate 列表中而被删除。数据转换提交后才执行删表，DDL 中断可重启继续；删表后的历史核查和回滚使用停机前的数据库备份。

历史商户身份、实际兑换者、缺失的付款证据、仍可能发生收款或结算的在途责任，不能从当前配置或相近时间的日志猜测，仍需按下表处理。用户身份和渠道配置继续使用已有启动迁移，无冲突的记录不需要手工改库。

| 签收项 | 需要的证据与结果 |
| --- | --- |
| 用户组 | 晋级沿用余额加已消费额度，不新增累计字段或回填要求；既有组不在迁移时重算，后续余额增减按晋级区间匹配。 |
| 历史订单 | 核对原商户、环境、应用、订单号、交易引用、应付金额/币种和原入账状态；不能用当前网关配置猜历史身份，已入账订单不得再次发额度。 |
| 实际兑换者 | `Redemption.UserId` 是创建者；只有可信兑换记录可确定 `redeemed_by_user_id`。缺少证据的记录列入人工核查清单。 |
| 唯一约束 | 预检订单号、用户请求键、供应商真实 namespace＋非空交易引用；人工核实重复交易，空交易引用使用 NULL，非空真实引用保留并检查唯一性。 |
| 金额和结构 | 检查整数最小货币单位、币种/精度、完整付款事实约束，以及订单和兑换字段；使用实际部署数据库验证。 |
| 异常记录 | 明确缺证据记录的隔离位置和最终处理责任，不伪造主体、交易号或签名材料满足新约束。 |
| 未完成订单 | 明确仍可能付款或重投的旧单验证材料、处理入口和责任人；本地过期不能消除收款责任。 |

历史成功充值和兑换记录不能再次增加现有余额。支付身份及兑换归属仍须以可信历史事实核定。

### 派生字段收敛

迁移 `202609090003` 删除订单的 `order_amount`、`gateway_no`、`status`、`currency_exponent`，网关的 `protocol_profile`，以及任务的 `prepared_at`、`quota`。API 中原有展示字段继续由保留的金额、交易、支付状态、币种、网关身份和任务最终额度生成；筛选及统计也只读取这些事实。

升级前停止全部旧 writer。启动先执行上述历史数据转换，再逐批核对派生字段，包括软删除记录；新旧值冲突时停止，不自动选择金额、交易或状态。无法从旧记录确定 `charged_quota` 等事实时仍须先核查，不能用默认值替代。空旧表可直接清理。报价明细、凭据使用版本及其他历史核查信息保留。

全部核对通过后，旧 `closed` 映射为持久化的本地窗口到期；已有上游关单事实保留，付款事实及余额不变。关闭入口不能重新发起准备，仍核查迟到支付并按原单入账。旧 `failed` 仅在已有准备拒绝事实时可映射，缺少失败原因时停止，不能猜测上游执行结果。API 的 `status`、筛选和排序统一按付款成功、本地或上游关闭、准备拒绝、待确认的优先级派生。

状态映射提交后才删列；DDL 中断可修复原因后重跑。列检查读取精确元数据，支持 SQLite 未加引号的历史建表 SQL。SQLite 使用当前依赖内置版本支持的原生 `DROP COLUMN`，保留表内其余约束和索引。完成后核查未付款/已付款/已关闭筛选、交易号查询、金额统计、任务查询和重复回调。恢复旧程序须停写并恢复匹配备份，同时核查备份之后的资金事实；不保留新旧 writer 并行路径。

用户已消费额度现在与消费结算同事务写入。部署前应停止新工作、排空短请求并刷完旧实例的已消费批量统计，再停止旧 writer；不得新旧混跑。已有错误分组可在该用户操作结束后通过管理员“重新计算用户组”（额度增减为 0）修复，此操作不补写资金事实。

## 启动验证

- 核对实际使用官方微信 SDK：`go list -m -json github.com/wechatpay-apiv3/wechatpay-go` 应为 `v0.2.20` 且无本地替换。验证证书串行刷新、失败后保留证书，以及凭据轮换和服务关闭时的任务退出；APIv3 密钥轮换须协调商户侧服务，并验证原单认证查询可用。
- 启用 Stripe 前完成 [Adaptive Pricing 固定报价前置](#stripe-固定报价前置)：逐环境核查 Dashboard 设置并保留新测试订单的币种/总额证据；本地配置 ready 不替代该签收。
- 在隔离商户/测试环境核验启用产品的冻结金额、原始通知验签、重复通知、迟到支付、停用后的历史通知，以及支持产品的查询和关单。
- 核对 SQL 订单状态、余额和用户组同成同败；验证跨进程并发及 namespace 交易唯一性。
- 检查用户组策略发布就绪、其他实例的新请求和既有连接下一工作单元能够读取最新归属和策略。
- 新前端在确认冻结金额后读取同一订单的最新状态；到期、处理中、已到账或读取失败时不能执行旧付款动作。

## Stripe 固定报价前置

本适配器锁定 `stripe-go/v80 v80.2.1` 和 `2024-09-30.acacia`，只接受冻结的 CNY/USD 订单应付总额。收银台自动换币（Adaptive Pricing）不在本次支持范围内。

Stripe 在 [2024-11-20.acacia 变更记录](https://docs.stripe.com/changelog/acacia/2024-11-20/adaptive-pricing-param)中才新增逐 Session 的 `adaptive_pricing` 参数，用来覆盖 Dashboard 设置；官方升级说明对应 API 头 `2024-11-20.acacia`、Go SDK `v81.1.0`。[当前锁定版本的创建参数](https://docs.stripe.com/api/checkout/sessions/create?api-version=2024-09-30.acacia)不包含该字段。因此，本实现不把 `Params.AddExtra("adaptive_pricing[enabled]", "false")` 当作锁定协议保证：该方法只能添加请求字段，不能让服务端支持未承诺的参数。未使用真实商户凭证验证旧版本服务端是否容忍该额外字段。

启用 Stripe 新单前，部署负责人必须在该商户实际使用的 sandbox/test 和 live 环境的 [Dashboard 支付设置](https://dashboard.stripe.com/settings/adaptive-pricing)关闭 Adaptive Pricing，并保存配置与新测试订单的币种/总额核验记录。`SetupStatus=ready` 只表示本地配置及 webhook 配置完成，不证明 Dashboard 的这项设置；签收前保持该 Stripe 网关禁用。缺少此前置时，收银台换币可能使返回的付款金额/币种不符合原订单，无法自动入账。

[Stripe 官方说明](https://docs.stripe.com/payments/currencies/localize-prices/adaptive-pricing?payment-ui=stripe-hosted)指出，关闭设置不影响已经发生换币的 Checkout Session。发现误启用时先停止新单、关闭设置并验证新测试订单，保留旧订单的历史通知和核查责任；不能放宽金额校验或重新创建支付来处理这些旧单。

未来需要由代码逐单关闭该功能时，应单独升级到支持该参数的 API/SDK，加入显式 `enabled=false`，并验证请求字段和 webhook 版本后再删除 Dashboard 关闭前置。本次保持锁定版本，不增加兼容分支。
