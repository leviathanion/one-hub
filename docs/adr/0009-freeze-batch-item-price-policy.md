# Freeze Batch item Price Policy at submission

> Superseded by ADR-0011 and ADR-0012. Batch is not part of the ordinary-user initial surface, and the new plan does not retain the observe-only Batch metadata and settlement subsystem described below.

Batch input uploads retain a bounded projection of the exact `custom_id`, endpoint, request model, requested service tier, and hosted-tool pricing context. The hosted-tool context contains only web-search service/context size and image quality/size. Chat Search models on `/v1/chat/completions` reconstruct exactly one submitted web-search fixed fee for each successful item, independent of provider output omissions or duplicates. A successful Batch submission freezes one Price Policy and explicitly present Batch input/output multipliers per distinct request model; a present `0x` remains free while an absent value inherits `1x`. Batch retrieval later binds that snapshot to the provider output file. Output JSONL items join by byte-for-byte `custom_id`, so whitespace-distinct and mixed-model items retain their individual request pricing boundary.

Settlement still prefers an explicitly configured exact or wildcard actual-model price. An unregistered provider version or alias uses the item's frozen request Price Policy and Batch multiplier. A legacy or uncorrelated output with no registered actual model is marked unpriced and never falls through to the resource request's empty-model global price. A terminal Responses item that omits hosted-tool pricing fields is reconciled from its submitted request context. Successful output dialects without response IDs use a stable channel/Batch/output-file/`custom_id` observation identity, so repeated output-file reads settle once.

The Batch create row also freezes the submitter user, token, token name, routing-group fields, group ratio, source IP, and user agent needed by the existing observation log path. Output reads use that snapshot for attribution and price arithmetic even when another administrator fetches the file; the observation identity is unchanged. The snapshot remains the historical attribution fact if the user or token is later deleted. Missing legacy metadata is diagnosed and never falls back to the reader. This snapshot does not introduce Batch ownership or extend observe-only Batch handling into durable quota settlement.

The schema adds input-item and Batch-job pricing metadata tables through ordinary automatic migration, including `expires_at`-leading indexes for lazy expiry cleanup. Existing Batch jobs are not backfilled because their submit-time catalogue cannot be reconstructed. Metadata expires after 30 days and expired rows are lazily deleted on later metadata writes. Upload projection is capped at 50,000 items and 8 MiB per JSONL line. Successful upload/create/list/retrieve control responses up to 1 MiB are committed to metadata before their status/body is published downstream; output copying performs only bounded in-memory lookups. Metadata database work has a two-second deadline. A provider success followed by local metadata failure can still lose observation billing; eliminating that boundary would require the durable outbox intentionally excluded by the bounded-observation design.
