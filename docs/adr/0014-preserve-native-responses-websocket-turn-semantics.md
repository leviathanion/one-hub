# Preserve native Responses WebSocket turn semantics

Native Responses WebSocket client frames are forwarded in order while the proxy keeps only a bounded FIFO of turn observations. The synchronously read first `response.create` is admitted to the actor mailbox before the client read pump starts, so every later client frame observes the opening turn state. A second `response.create` is not rejected as `session_busy`; each turn keeps its own client model and is accepted only when the already selected channel supports that exact model, without switching channels or rewriting the model. Exact support comes from the channel's explicit model set, including configured wildcards; the relay does not infer alias equivalence from model names, because doing so would claim provider acceptance and wire identity without channel-owned evidence. Administrators may list both aliases or use a deliberate wildcard when the upstream account accepts them. `response.inject` and its acknowledgements remain provider wire data, while an internal pending-inject count prevents observation from ending before all `inject.created` or `inject.failed` acknowledgements arrive.

Public Responses terminal events remain `response.completed`, `response.failed`, and `response.incomplete`. A provider-specific terminal discriminator may be normalized only by its provider adapter when the provider contract proves one of those exact meanings; all payload fields remain provider data. A missing status has no generic meaning: it may be accepted only when the provider-owned discriminator itself has a fixed terminal meaning, while cancelled, unknown, or otherwise unrepresentable outcomes fail explicitly. This supersedes only the first-model-lock decision in ADR-0006 and does not authorize an HTTP bridge or a translated session state machine.
