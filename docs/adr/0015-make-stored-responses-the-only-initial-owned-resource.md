# Make Stored Responses the only initial owned resource

The first supported stateful surface is limited to Stored Responses. A Responses request with omitted or true `store` creates durable principal/channel/account ownership as soon as `response.created` exposes its ID, and continuation plus supported retrieve, delete, and input-item lifecycle operations route strictly to that owner for the provider retention period. The ownership write must commit before the first ID-bearing JSON, SSE, or WebSocket event is delivered; a write failure ends the relay even if the provider may retain an orphan. Explicit `store:false` creates no durable ownership: continuation on the same Native Responses WebSocket remains connection-local, while a later independent request may enter ordinary scheduling only when a bounded user-scoped provenance proof still exists. The proof uses the existing memory/Redis affinity backend, includes `UserId` in its key, and defaults to a one-hour TTL. Background Responses, Stored Chat, conversations, saved prompts, and external file, vector-store, container, or Skill references fail before provider work until their own complete lifecycle is supported.

The owning principal is `UserId`; the creating `TokenId` is retained only for audit, so credential rotation does not orphan a Stored Response. The exact `channel_id` is the upstream account boundary: an unavailable owner fails instead of falling back, and changing that channel to another provider account is an administrator-controlled breaking operation. A known owner mismatch and an ownership miss both fail closed for ordinary users; only an administrator-pinned relay may attempt an unknown ID. The proxy never invents an owner from the selected channel.

Ownership remains through the provider retention period plus a seven-day grace period, initially 30 + 7 days. A successful delete converts the record to a tombstone retained through the same horizon instead of deleting it immediately.

After a provider has returned a new stored Response ID, ownership commit uses a bounded context detached from downstream cancellation. Any later ownership or delivery failure is provider-accepted work: it may leave an invisible orphan and cannot trigger provider retry. Billing follows ADR-0030：有 provider usage 才 Confirm，否则 Cancel。

Consumers that may stop before a generic provider stream finishes use close-and-drain rather than a bare close. Closing cancels emitter-based readers; draining additionally releases legacy handlers that may already be blocked in a raw channel send. This lifecycle rule applies to the Stored Responses owner barrier and other generic stream aggregators, without changing provider protocol semantics.

The initial owner-table rollout is a full-stop breaking cutover. Responses created before the rollout are not backfilled from legacy affinity, selected channels, or provider probes; ordinary access to those IDs becomes an ownership miss after upgrade. Administrator-pinned relay remains the only unknown-ID escape hatch. Requiring compatibility for pre-cutover IDs would trigger a separate two-release migration decision rather than a permanent fallback branch.

`/responses/compact` returns a distinct `response.compaction` result rather than creating a Stored Response lifecycle resource. Its `output` items are replayed as input to continue a compacted conversation. The proxy therefore does not create a `response_owners` row merely because the compacted result also has an `id`; identifier shape is not lifecycle evidence. Revisit this boundary only if the upstream public contract explicitly makes compacted IDs valid targets for retrieve/delete/input-items or `previous_response_id`, at which point the full authorization, retention, and exact-channel lifecycle must be added together.

Omitted or true `store` may select only a channel that explicitly declares the complete Stored Response lifecycle per operation. Built-in adapters provide project defaults; custom channels require administrator opt-in. Capability is not inferred only from channel type, `CompatibleResponse`, or a runtime probe. `store:false` retains the established channel and adapter scheduling rules.
