# Require native Responses WebSocket upstreams

A client Responses WebSocket request is routed only to a channel explicitly capable of a Native Responses WebSocket operation. Native means a real upstream WebSocket rather than an HTTP/SSE bridge; it does not by itself promise exact-wire application events. A registered provider adapter may perform a narrow, explicit lifecycle mapping when its native Responses operation uses a provider-specific discriminator, but only for statuses with a lossless public representation. Unsupported channel combinations and request shapes fail before provider work; an unrepresentable provider result observed after work fails closed without replay. Existing HTTP adapters retain their established behavior because this decision is specific to the WebSocket transport. This gives up bridge coverage for HTTP-only providers while keeping provider dialect differences at the adapter boundary.
