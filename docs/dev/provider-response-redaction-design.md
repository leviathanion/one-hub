# 对客错误信息脱敏方案

## 决策

本方案遵循两个边界：**脱敏尽力而为；脱敏不能干扰透明转发正文。** 系统日志保留原始诊断，不纳入脱敏范围。

脱敏只生成返回客户端的错误诊断副本，包括 HTTP 错误、SSE/WS 中明确的错误对象、关闭原因，以及任务查询中的失败原因。正常响应、模型文本、工具参数、usage、用户 metadata、文件、音频、字幕和重定向正文保持原有交付语义，即使内容与实际渠道凭据相同，也不进行替换。

不能解析、不能识别或超出脱敏预算时，返回原文。脱敏结果不决定 HTTP 状态、是否关流、渠道健康、重试、owner、usage 或计费。真实 I/O 失败、权限、owner 屏障、协议转换能力及既有资源限制仍由原来的责任层处理。

本决策取代此前“全正文扫描、失败即拒绝”的方案，也取代以脱敏为理由统一改写账号错误码的规则。既有 HTTP 响应头公开策略继续适用；错误码、类型、参数路径和关联 ID 保留上游值。没有数据库迁移或新增开关。

## 职责与执行点

| 位置 | 职责 |
| --- | --- |
| provider / requester | 构造请求、保存实际连接的认证快照，提取原始错误和执行事实；不因脱敏修改正常响应 |
| relay / runtime | 使用原始错误、事件和用量判断控制状态，按既有契约选路、交付和结算 |
| `common/providerresponse` | 共享的错误诊断脱敏函数；输入只读，输出可以直接回退为原文 |
| `common/surface`、错误原文回放出口 | 生成 HTTP / 类型化错误的对客副本，处理改写后失效的表示头 |
| SSE / WS 已有事件出口 | 只修改明确错误对象；保留事件外围字段、行结束符和交付时机 |
| 任务 DTO / 独立错误出口 | 处理明确的失败原因和错误描述；不修改存储数据、任务结果或正常响应 |

错误观察与对客呈现分开，避免脱敏改变消息后影响分类、重试或渠道禁用。服务器日志、内部观察和数据库继续使用原始诊断。没有全局 Gin `ResponseWriter` 包装器、额外缓冲队列或另一套协议处理链。

## 错误处理规则

`SanitizeErrorPayload(raw, credentials...)` 只识别顶层 `error` 对象、`response.error` 对象以及明确的 `type: error` 事件。SSE 的 `event: error` 和调用方已确认的纯错误响应使用 `SanitizeErrorResponse`，允许处理平铺错误对象。普通 `code/message` 字段不会使成功正文自动成为错误。

未知字段不采用封闭白名单。定位错误对象时用 Go 标准库 `encoding/json/jsontext` 跳过其他值；修改时拼接原始字节，只重编码命中的诊断值，保留字段顺序、未知子树、大整数和其他数字写法。

错误诊断内采用两类匹配：

- 实际连接持有的已知凭据，以及明确的凭据、账号字段名。
- 文本中明确的密钥格式、认证赋值和账号标识；正常协议词和普通业务描述保留。

`code/type/param`、关联 ID、model 和 sequence number 保留，包括开放的结构化错误码。错误对象之外的未知兄弟扩展、成功 metadata 和正文不扩展扫描；无法确定归属时允许遗漏。字符串形式的 `error` 可能是 OAuth 错误码，保留其值。

类型化错误只对诊断字段做 JSON 转换，协议字段保留原始 Go 类型和值。呈现层先基于原始错误完成既有协议映射，再生成脱敏副本；凭据快照和脱敏命中情况不参与 HTTP 状态决策。

单条 JSON 的脱敏预算为 1 MiB，诊断遍历深度为 64。重复键、截断、多根 JSON、非法编码或预算不足均回退为原文，不生成本地 502、不 abort/reset、不吞事件、不伪造完成状态。预算仅限制附加处理成本，不是正文接收限制。

已知凭据按解码后的诊断字符串匹配。替换后若边界拼接又产生相同凭据，整个诊断值替换为占位符；不进行无界循环。跨事件拼接、任意编码、未知凭据与所有个人信息的检测不在保证范围内。

HTTP 错误原文实际发生改写时移除旧的长度、编码、摘要和 validator 等表示头；未改写则保留既有公开策略允许的头部。错误响应头可移除直接含已知凭据的值。成功响应与重定向不增加凭据扫描。

## 为什么重构

此前反复出现的问题主要来自错误的范围：把脱敏做成每个成功 JSON、SSE 事件和 WS 帧的强制安全关卡，导致必须解释未知字段角色、扫描正文、维护多种媒体类型，并把解析失败接入交付失败和重试控制。这超出了代理需要承担的职责。

本次删除全正文凭据匹配、成功元数据改写、音频 JSON/文本脱敏分类、重复键安全拒绝和脱敏专用中断路径。保留实际连接凭据快照，因为凭据刷新或重连后，迟到的错误仍属于原连接；不新增跨请求存储或历史凭据追踪。

没有把普通成功响应中出现凭据的案例继续作为“泄漏缺陷”修补。测试改为要求这些内容保留原文；错误信息尽力处理。此前性能数字测量的是不同保护范围的旧方案，不作为本版收益承诺。

独立修复仍包括：错误控制解析必须消费完整 JSON，避免尾随垃圾被当成有效健康证据；保留原始 provider 帧的 Realtime 分支不因附带本地错误而改变来源；补充实际握手认证字段；Docker 链接变量修正为 `one-api/common/config.Version`。

## 公开实践的参考边界

此前调研的公开资料支持“明确处理对象和执行边界”，不能视为这些公司所有服务都采用相同实现：

- [Google Apigee 调试脱敏](https://docs.cloud.google.com/apigee/docs/api-platform/security/data-masking)：调试数据的处理与业务转发分开。这种边界划分适用；本项目不处理系统日志。
- [腾讯云 AI 网关数据脱敏](https://cloud.tencent.com/document/product/1826/134823)：区分处理对象和失败策略。网关提供正文脱敏能力，并不意味着透明代理应默认扫描正文。
- [字节 BSave 数据切面工程](https://developer.volcengine.com/articles/7605799987732971558)：按协议与明确的数据边界集中处理。其存储 Sidecar 和插件体系不适合本项目当前规模。

Go 中间件或拦截器可以统一错误呈现规则，但通用 `Write` 只能看到字节片段，不能天然区分错误对象与模型正文。这里复用现有 HTTP 错误呈现和 SSE/WS 消息边界，不在 I/O 层新增拦截器。

## 构建与验证

构建基线仍为正式 Go 1.27.1，Docker 和发布 CI 使用同一版本，JSON 定位使用标准库 jsontext。macOS 最低支持版本随该构建基线提高至 13；未整体迁移业务 JSON 到 `json/v2`。

验收以客户端结果为准：

- HTTP JSON、文件/音频、字幕、重定向、SSE 和 WS 的正常内容逐字节保留；文本和工具参数在跨协议转换后仍保持内容。
- 错误消息尽力脱敏，状态、错误码、关联字段和未知数字保留；原始观察对象不变。
- 解析失败和超限原样返回，首事件与已提交流均不因脱敏中断；不增加上游调用。
- CR/LF/CRLF、多行 data、EOF 尾部和真实客户端写入失败遵循原有交付与计费规则。
- 认证刷新、连接快照、渠道健康与重试读取原始事实；系统日志不进入脱敏链。

执行命令：

```sh
GOTOOLCHAIN=go1.27.1 go test ./... -count=1
GOTOOLCHAIN=go1.27.1 go test -race ./common/providerresponse ./common/requester ./common/surface ./runtime/session ./providers/openai ./providers/codex ./providers/xunfei ./relay/...
GOTOOLCHAIN=go1.27.1 go test ./common/providerresponse -run '^$' -fuzz '^FuzzSanitizeErrorPayload$' -fuzztime=20s
```

本地 HTTP/SSE 与真实 WS 连接测试不替代生产渠道验证。生产吞吐与 p99、真实 OAuth/云服务、Docker 镜像启动以及 macOS/Windows 原生运行仍需对应环境验证；本方案不对这些尚未测量的结果作承诺。
