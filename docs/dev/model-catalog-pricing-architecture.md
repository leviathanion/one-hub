# 模型信息与价格关联调整方案

## 文档状态

- 状态：当前实现。
- 适用范围：明确模型信息、展示归属与售价的关联职责；停机一次切换，不保留兼容逻辑。

## 领域模型变化

- **以模型为统一业务条目**：描述、展示归属、可用性和匹配售价一起查询与展示；元数据和价格分表存储不意味着业务解绑。缺少描述不阻断调用，缺价由既有计费准入处理，不据此判断模型不存在。
- **模型归属属于模型信息**：保留管理员配置的展示分类，关联从 `Price` 移到 `ModelInfo.owned_by_id`；不把现有品牌、托管商分类强制重分类为发布方，名称、图标、ID 及内置／自定义管理规则保留。
- **报价 provider 与展示归属解绑**：models.dev 价格导入不设置模型归属；独立的归属匹配根据目录中的 API 服务提供方提供建议，由管理员映射到本地分类后保存。模型开发者与服务提供方分开，不从 canonical 作者关联推断本地归属。

## 持久化与读取变化

沿用现有表名，通过模型名关联描述与售价：

| 表 | 变化 |
| --- | --- |
| `model_info` | 新增可空 `owned_by_id`；清理重复记录后，为精确模型名建立唯一约束，大小写不同的模型不得被合并 |
| `prices` | 删除 `channel_type`，同步删除默认价格及发布流程中的归属字段 |

归属关联写入与分类删除须保证并发引用完整性；仍被引用的分类拒绝删除。

保留 `model_info` 作为模型价目响应中的只读组合字段，不再于价格发布时固化元数据。查询按对外精确模型名批量读取描述和归属，装配到响应副本；不修改共享计费策略，也不随上游映射或回显改换描述。同步移除 `ModelOwnedBysInstance` 展示缓存及刷新调用。

目录读取仅用于组合展示，不进入计费查价、选路或价格发布；查询失败需明确报错或记录，不能伪装成目录缺失或转成无价。通配售价可以供多个模型使用，描述和归属仍按各自精确模型名关联。

模型视图保留对外模型名，匹配售价保留原始规则键。价格管理和导出枚举真实的精确／通配规则，不把模型视图中命中的通配售价展开成精确价格，否则再次覆盖导入会改变未来模型的计价。

## 接口与页面变化

- 直接修改现有 `/api/model_info`、`/api/model_ownedby`、`/api/ownedby`，不增加新旧入口。模型的归属选择写入 `ModelInfo.owned_by_id`。
- 售价条目顶层删除并严格拒绝 `channel_type`。导入沿用现有 `model_info` 原始只读 JSON，不参与售价校验、摘要或持久化，不递归解释其中的字段。页面同步仅保留 models.dev，移除自定义价格 URL 与定时更新；共享预览／应用 API 保留。
- 模型列表、详情和价格页面继续获得描述、归属与价格的组合视图；编辑描述或归属后刷新展示，不等待售价变更。
- 移除 Gemini 列表和单模型查询对价格归属的判断，改用现有分组与协议候选规则，覆盖 Gemini、Vertex。未知归属不再导致模型不存在，公开组合视图不得泄露跨分组可用性或管理配置。
- 归属筛选改读目录；通配售价行不推断单一归属。“未设置归属”与“未配置售价”分开显示。

## 批量维护归属

价格页和模型详情页分别提供“手动设置归属”和“从 models.dev 匹配归属”两个入口，共享模型选择与提交规则。候选按精确模型名合并已有模型信息、精确价格和全部渠道配置的对外模型，包含禁用渠道；不采用上游映射名，不展开通配价格。无模型信息的条目仅作为候选展示，保存非空归属时才补建最小目录。也可粘贴尚未配置的新模型名。分页可选择每页 25、50、100 或 200 个模型，切换时返回第一页并保留已选模型。

以下接口均要求管理员权限，不改变公开模型信息列表的读取范围：

| 方法与路径 | 合同 |
| --- | --- |
| `GET /api/model_info/ownership/catalog` | 返回 `model`、`name`、`owned_by_id`、`has_info`；目录缺失与查询失败分别处理 |
| `POST /api/model_info/ownership/suggestions` | 接收 `models`，返回各模型的 `providers: [{id, name}]` 和 `matched`、`unmatched` 或 `conflict` 状态；只读取来源，不写库 |
| `POST /api/model_info/ownership/batch` | 接收 `mode` 和 `items: [{model, owned_by_id}]`，返回 `created`、`updated`、`unchanged`、`skipped` 数量 |

建议与写入请求每次最多 500 项、正文最多 1 MiB。模型名保持精确大小写，非空且不超过 100 个字符，不接受 `*` 通配项。写入必须显式提供 `owned_by_id`，使用本地分类 ID；同一模型的重复相同赋值去重，不同赋值拒绝。

`fill_missing` 在数据库执行时仅补空归属，目标必须非空；`replace` 明确覆盖所选模型，`owned_by_id: null` 表示清空。清空不存在的模型不创建空目录。已有目录仅更新归属和变更时间，保留描述、能力及其他信息；相同赋值不改变变更时间。

一批修改在单个事务中完成，分类按 ID、模型按精确名排序处理。复用分类写入／删除锁及精确模型名唯一约束；任何错误整批回滚。明确覆盖沿用提交时赋值语义，不承诺预览后的旧归属保持不变。成功后重新读取组合视图，不发布价格、不改变价格版本，也不维护额外缓存或来源映射表。

models.dev 建议复用价格同步的有界抓取和来源解析，但不依赖价格转换成功。按来源中的精确模型键收集顶层 provider，ID 使用 provider 键，显示名称使用 provider 的 `name`，名称缺失时回退 ID。不同 provider 下的同名模型标记冲突，即使它们有相同开发者或显示名称；没有精确模型键时保持未匹配，不通过前缀猜测。界面按 provider ID 分组和维护本次映射，显示名称仅用于展示。未匹配、冲突或尚未映射的选中项不能自动提交。

例如 `@cf/moonshotai/kimi-k2.6`、`@cf/moonshotai/kimi-k2.7-code`、`@cf/nvidia/nemotron-3-120b-a12b` 在 Cloudflare Workers AI 目录下，均建议映射 `cloudflare-workers-ai`；它们的 canonical 开发者 Moonshot AI 或 NVIDIA 不影响该建议。Moonshot 官方 API 目录中的模型则属于另一个 provider，不因同属 Kimi 而共享映射。

本次修正将建议接口的 `labs` 替换为 `providers`，前后端需同步部署，已打开的管理页面需刷新；调用该接口的外部脚本也需适配新字段，并按 ID 而非名称映射。不保留作者字段承载服务提供方的新含义。已有归属记录不会自动重写；需要纠正此前按作者保存的分类时，管理员重新查询并明确选择覆盖。此修正没有数据库结构迁移，回滚需配套回滚前后端；回滚代码不会撤销管理员已保存的归属。

## 一次性迁移

1. **盘点旧归属**：模型集合取现有目录、精确售价和全部渠道配置的精确模型并集，包含禁用渠道。解决重复目录，按旧价格匹配结果原样迁移有效分类 ID；悬挂引用置空并报告，不因分类是托管商而清空。
2. **补齐关联**：仅为存在有效旧归属但缺少目录的精确模型补建记录，不给无描述、无归属的模型造空目录。未来新增模型不再从通配售价继承归属，不创建通配目录记录。
3. **备份与发布**：通过 PR 合入代码，由 CI 构建发布 Docker 镜像。更新前停止旧实例及后台写入、排空在途结算并备份，再拉取发布镜像启动；不直接替换本地编译的线上二进制。
4. **启动迁移**：主实例在自动建表、默认数据写入、worker 和 HTTP 服务启动前，由 Go 代码完成上述数据转换、增加目录约束及删除价格归属列；目标结构仅校验，不重复改写。副实例不执行迁移，旧结构、冲突或半迁移状态阻止其继续初始化。空库直接建立目标结构，分类种子与 ID 规则复用。
5. **恢复服务**：就绪检查通过后恢复流量；前端、同步脚本和价格文件使用新字段契约。迁移失败恢复备份后重启，恢复业务写入后则需核对新增账务与任务数据，不能直接覆盖旧备份。

## 验收重点

- 模型组合视图的描述、归属和匹配售价正确；元数据跨实例更新无需价格发布，目录读取故障不影响计费策略加载和结算。
- 价格导出再导入保留通配规则，可携带 `model_info` 但只更新售价；售价条目顶层拒绝 `channel_type`，不递归校验元数据。
- 相同计费输入下金额一致，价格锁定和并发发布不受元数据修改影响；私有分组及 Gemini／Vertex 模型可见性正确。
- 在支持的数据库上验证目录去重、并发引用、空库启动、旧库启动迁移、重复启动及备份恢复；迁移失败不得开始服务，启动不能重建旧字段或覆盖管理员目录配置。
