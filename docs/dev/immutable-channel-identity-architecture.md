# 渠道编辑确认方案

## 决策

本方案替代不可变 channel incarnation 方案，见 [ADR-0035](../adr/0035-confirm-channel-edit.md)。保留现有文档路径以维持链接。

渠道 ID 表示可编辑的管理记录。管理员在同一表单修改原渠道；每次保存前统一展示影响说明，确认后才发送更新请求，取消保留当前表单。标签编辑遵守同一交互，并说明修改会应用到标签下的渠道。新建渠道不弹编辑确认。

不检查任务或其他资源占用，不增加后端确认字段、预检接口或资源查询。弹窗只负责用户界面的明确操作意图；直接调用管理 API 仍按现有管理员权限和配置校验处理。

## 影响说明

修改地址、账号或凭据可能导致已有任务的查询、续作、结果获取，以及已存储响应、文件、会话等上游资源的后续访问失败。模型、分组、路由或功能配置的修改也会影响后续请求。

编辑原地保存，不创建副本、不迁移 owner、不重置统计，也不引入资源版本表。任务和 Stored Response 继续引用原渠道 ID，后续请求读取该渠道的新配置；渠道 ID 不再保证上游账号身份永久不变。

## 服务端边界

- 管理编辑允许修改类型、凭据、BaseURL、组织/项目请求头、Other 账号字段以及 Custom 端点，仍校验输入合法性与协议支持范围。
- 表单凭据未修改或留空时不提交 `key`，保留服务端最新值；显式提交空凭据返回错误。
- 身份修改与凭据生命周期写入使用渠道行锁协调，不能覆盖未解决的 credential refresh fence。同账号 OAuth 轮换继续使用现有 claim/commit 流程。
- 身份变更递增 `CredentialRevision` 防止旧凭据操作提交，该字段只用于并发控制，不作为资源归属版本。元数据编辑不覆盖凭据和刷新状态。
- 标签编辑遵守现有可同步字段范围，不接受统一替换成员 key。整批验证与写入在同一事务中完成。
- 后台同步和内部普通更新不能隐式替换连接身份。成功提交后统一刷新路由和派生缓存，进入或离开 Codex 类型都处理相应缓存。

## 保留的约束与代价

已有请求仍按实际执行事实结算；编辑不重写已有资源 ID、计费 owner 或历史用量。不因后续资源访问失败增加自动切渠道或提交后的重试。普通资源透传要求启用渠道，owner 专用路径保留已有停用/软删除读取行为。

本方案不新增数据库列，不补造历史身份，也不执行旧方案中的 verified/legacy_unverified 迁移。以后若产品要承诺跨账号编辑不影响存量资源，需要另行设计真实的归属和迁移能力；弹窗不能提供该保证。

## 验证

- 编辑保存前没有更新请求；取消保留表单，确认只提交一次；再次编辑仍需确认。
- 标签编辑同样确认；新建渠道直接提交；保存失败后恢复可操作状态。
- 无任务表也能编辑；原 ID、未提交凭据、历史统计和状态保持正确。
- 普通配置编辑、身份编辑和显式空值写入符合字段语义。
- 非法配置或未解决凭据 fence 不写入，标签编辑失败整批回滚。
- 旧 refresh ticket 不能在新身份配置上提交，后台同步不绕过限制。
