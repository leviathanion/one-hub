# 条件倍率规则设计

## 文档状态

- 状态：当前实现，2026-09-08。
- 范围：`Price.rate_rules` 的条件匹配、统一倍率、计量项覆盖、配置与验证。
- 用户说明：[条件倍率配置](../use/pricing-rate-rules.md)。本文拥有开发契约；用户文档说明配置与收费结果。
- 旧固定规则从未上线，直接替换为新版结构；不实现数据库迁移或旧目录兼容。
- 定价决策见 [ADR-0018](../adr/0018-price-from-explicit-rate-rules.md)。结算继续遵守 [ADR-0033](../adr/0033-settle-atomic-price-components.md) 和 [ADR-0034](../adr/0034-read-configurable-policy-at-each-use.md)。

## 30 秒理解方案

**保留基础价格，让条件规则只调整倍率。统一倍率是默认值，局部倍率覆盖默认值。**

```text
可信计费事实 + 当前完整 Price Policy
                 ↓
按互斥取值／区间匹配；时间组按优先级匹配
                 ↓
组内按计量项解析覆盖关系，组间相乘
                 ↓
有效价格 → 证据完整性判断 → 现有计算与结算
```

| 保留 | 扩展 |
| --- | --- |
| `Price.input/output/extra_ratios` 及其计价单位 | `rate_rules` JSON 内部格式 |
| 模型匹配、Original Model Billing、用户组倍率 | 服务档位、速度、长度与日历条件 |
| 价格发布、现有 quota 换算与舍入边界 | 统一倍率和计量项独立倍率 |
| Billing Attempt、Price Component、Confirm/Cancel | 实际 Speed 的提取与证据传递 |

第一版仅作用于 `tokens` 价格中输入、输出及原有 token 调整链路支持的 `extra_ratios` 计量项。`times` 价格、独立工具价目、`ProviderIndependentUsageUnits` 的独立计价路径保持现有语义，不自动加入折扣。管理界面必须展示这个范围。

## 领域边界

| 概念 | 职责与来源 |
| --- | --- |
| Price Policy | 一个模型的完整基础价格、扩展倍率与条件规则；客户售价不等于上游成本 |
| 计费事实 | 适配器提取的实际属性与用量，以及 owner 记录的操作开始时间 |
| Rate Rule | 条件成立时对计量项施加的倍率调整 |
| 统一倍率 | 当前一条规则内的默认调整倍率，不是跨模型全局价格 |
| 有效价格 | 一份 Price Policy 与事实经过规则解析后的计价结果 |
| Price Component | 现有可独立确定收费的证据集合，不等于一个单价项或规则 |

适配器拥有 `ServiceTier`、`Speed`、token 包含关系及流式累计语义；共享定价层只解释声明过的事实。Claude 的 `usage.speed` 独立于 `service_tier`，不得将二者混为 Fast/Priority。新增协议事实需要代码适配，新增已支持属性的取值与倍率可以通过配置完成。

原始 wire 的未知字段继续按协议契约透传。这里的封闭 schema 只约束代理自己的价格配置，不是上游参数白名单。

## 持久化与配置结构

继续使用现有 Price 表；不新增条件表、规则表或价格历史库。`rate_rules` 保存一份新版 JSON，现有价格发布版本仍负责完整配置的原子发布。

| 字段 | 类型及含义 |
| --- | --- |
| `version` | 固定为 `2`，表示配置格式版本，不是价格发布版本 |
| `schedule.timezone` | 时间组内的 IANA 时区；有日历条件时必须显式填写 |
| `service_tier` | 取值互斥的服务档位规则数组，不依赖顺序 |
| `speed` | 取值互斥的速度规则数组，不依赖顺序 |
| `long_context` | 区间互斥的长上下文规则数组，不依赖顺序 |
| `schedule` | 包含 `timezone` 和有序 `rules` 的时间配置对象 |

四个组名是固定的，后端约束每组可用条件。服务档位只允许 `service_tier`，速度只允许 `speed`；长上下文要求 `input_tokens`，可选 `speed` 仅用于限制适用速度；时间组只允许 `weekdays/time`。

每条规则包含内部 `id`、`when` 和 `multipliers`，不保存名称。`id` 在整份策略内唯一且稳定，由界面生成，用于关联日志；界面和消费明细用条件摘要区分规则。省略规则组表示该维度不调整。

`multipliers` 包含可选 `all/input/output` 及可选 `extra_multipliers`。Go 使用 `*float64` 表达前三项，用 `map[string]float64` 表达独立项，通过 presence 区分省略与零。沿用现有数值存储和金额单位，不顺带迁移全部基础价格精度。显式 `null` 不等于省略，应拒绝。

### 完整配置示例

下面是一个 `rate_rules` 字段的完整值。模型、倍率和阈值仅用于说明组合语义，不代表任何上游的官方价目。

  ],
  "speed": [

  "schedule": {
    "timezone": "Asia/Shanghai",

      {

## 条件与选择语义

| `when` 字段 | 匹配方式 |
| --- | --- |
| `service_tier` | 仅服务档位组；实际值属于给定非空集合 |
| `speed` | 速度组的取值，或长上下文的可选适用速度 |
| `input_tokens` | 仅长上下文组；完整输入长度满足 `gt` 下界和／或 `lte` 上界 |
| `weekdays` | 仅时间组；当地日期的星期属于集合；周一为 1，周日为 7 |
| `time` | 仅时间组；当地时间属于每日 `[start, end)` 区间，格式 `HH:mm` |

枚举集合内部是 OR。长上下文的长度与可选速度限制是 AND；时间组的星期与时段是 AND。只有时间组允许空 `when: {}` 作为最后一条兜底。没有匹配时，该组提供恒等倍率 1。

服务档位／速度的取值集合不能相交；长上下文在适用速度相交时长度区间不能重叠。后端保存时校验，因此这些分组不依赖数组顺序，界面不提供排序。

只有时间组按数组顺序取第一条命中，界面明确显示“优先级”及“提高／降低优先级”，用于周末、夜间等优惠的覆盖。不同组各计量项的倍率相乘，固定评估顺序为 `service_tier → speed → long_context → schedule`，便于稳定复算与日志展示。

长上下文按完整输入长度选档，对整次操作使用该档倍率，不是对超过阈值的部分累进计费。缓存命中不会减少判断档位用的完整输入长度。Fast 不叠加长上下文时，在长度规则中明确限制实际速度，不能凭模型名推断。

### 时间事实

- 使用该 Work Action 进入本地计费流程时固定的开始时间，记录为 UTC instant。复用 owner 已有的合适时间字段；不能用整个 WebSocket 连接建立时间代替每个操作开始时间。
- 同一次操作跨过时段边界不换档；不按流式 chunk、执行秒数或完成时间重新划分峰谷。
- 时间跨午夜时，`23:00 → 07:00` 表示每天 23:00 之后或 07:00 之前。星期按该 instant 的当地日期判断：周五 23:30 不属于周末，周六 00:30 属于周末。
- `start == end` 拒绝，全天条件通过省略 `time` 表达。UTC 转当地时间天然处理夏令时；重复的当地时刻使用相同规则，不存在的当地时刻没有对应操作。
- 固定开始时间不等于冻结价格。各使用阶段仍读取当前完整发布，管理员更新规则、时区或倍率可能改变后续结算结果。
- 持久 owner 若未来进入本规则支持范围，开始时间必须来自现有持久事实或同一 owner 内持久化的字段。历史操作缺少该事实时不得用重启／轮询时间伪造；接入前需要明确迁移处理。本次不扩大异步按次计费支持面。

## 倍率覆盖与计算

对某一命中规则和计量项，只选择一个倍率：

```text
extra_multipliers[计量项]（显式存在时）
              否则
input 或 output（按既有计量项归属，显式存在时）
              否则
all（显式存在时）
              否则
1
```

`all` 是默认值，不能额外再乘一次。普通输入／输出直接从相应侧倍率开始解析。缓存读取、5 分钟写入、1 小时写入使用各自既有 key，不能因为名字相似混用 provider 证据。

| 规则倍率 | 普通输入 | 输出 | 缓存读取 |
| --- | ---: | ---: | ---: |
| `all=0.5` | 0.5 | 0.5 | 0.5 |
| `all=0.5, input=0.8` | 0.8 | 0.5 | 0.8 |
| `all=0.5, output=0.8` | 0.5 | 0.8 | 0.5 |
| `all=0.5, cache_read_input_tokens=1` | 0.5 | 0.5 | 1 |
| `all=0, cache_read_input_tokens=1` | 0 | 0 | 1 |

对计量项 `k`，`M(k)` 是所有命中组分别解析出的倍率之积。缓存的基础价仍来自既有 `input × extra_ratios[key]` 及现行价格读取回退规则，再乘 `M(k)`。独立项覆盖只影响当前规则，不会撤销其他组的倍率。

例如基础输入 $3／百万 token、缓存倍率 0.1，长上下文规则 `input=2, cache_read_input_tokens=1`：普通输入为 $6，缓存读取仍为 $0.3。再命中夜间 `all=0.5` 后，两者为 $3 和 $0.15。

计算层应直接构建每项有效价格，不能依靠“独立倍率除以输入倍率”实现覆盖，否则 `all=0` 或 `input=0` 会产生除零或错误免费。也不能将 `all` 乘到含独立工具费用的整笔总额。避免逐规则中间舍入；最终金额沿用既有组件换算边界，明确的全零有效价格必须允许零费用。

## 证据、计算与生命周期的共享边界

1. **先选完整价格策略。** 继续使用现有模型匹配与 Original Model Billing，一次求值不能混用不同模型或不同发布中的基础价、扩展倍率和规则。
2. **再评估规则与价格依赖。** 最终档位和速度使用上游证据。预扣维持现有公式；试算中输入的模拟值不能冒充可用于 Confirm 的证据。
3. **检查 Price Component。** 总量、缓存和媒体分区的依赖保持原子性。即使独立倍率让某项免费，也不能凭空构造其数量或绕过其他计量项所需的分区证据。
4. **复用一个有效价格解析器。** 实际计费、证据完整性判断、试算与日志展示共用结果；运行时派生，不新增跨请求缓存或第二份价格事实源。
5. **交回既有结算 owner。** 规则不产生扣款、退款、换渠道或重试权限。

条件求值要区分“确定不匹配”和“缺失／冲突而无法判断”。高优先级规则无法判断且可能改变金额时，不能跳过它选择后面的便宜或昂贵规则。只有现有证据可证明所有剩余可能结果一致时，才能继续确定计价；第一版无法证明的情况使用现有组件缺证据／冲突处理，不建设任意表达式等价证明器。

上游报告未知但有效的枚举值，与字段缺失不是一回事：未知值按显式集合、兜底或恒等倍率处理，并记录诊断。现有 `ServiceTier` 的空值／auto 默认语义保持不变；新增 Speed 的省略含义由适配器依据协议契约说明，不能直接套用 ServiceTier 的默认处理。规则完全不依赖某个属性时，不因它缺失而新增计费阻断。

## 保存校验与界面

- 拒绝未知配置版本、条件字段、规则组和当前调整链路不支持的计量项 key；属性值允许配置未来的非空枚举字符串。
- 倍率必须有限且非负；0 有效。同时约束组合倍率和金额计算的溢出，不能只校验单个字段。
- 输入长度边界是非负整数；存在双边界时 `gt < lte`。拒绝空集合、非法星期、无效时区和时间。
- 每份配置的当前上限为总计 64 条规则、每个枚举集合 32 个值、id 100 字节、规则 JSON 64 KiB；不为此引入新的管理员配置层。
- 拒绝重复 id、跨维度条件、非时间组的重叠及时间兜底之后的规则。时间组其他合法重叠由显式优先级解释。
- 前端默认只展示统一倍率，展开后设置输入、输出及缓存等覆盖；继承值是派生显示，不能自动写入覆盖字段。
- 使用有标签的输入、明确的继承／自定义状态和关联错误信息；时间优先级支持键盘可操作的提高／降低按钮，不能仅靠拖拽。
- 日志沿用现有非权威投影，记录价格发布版本、实际匹配事实、操作时间、命中组及规则 id、各项有效倍率。日志不是新增账本。

## 配置边界与链路入口

旧固定规则未上线，因此删除旧 schema 和求值分支，不创建迁移、旧格式导入转换或降级开关。配置入口仅接受 `{}` 清空或新版 v2；未知旧字段返回错误。

保留已有更新语义：省略 `rate_rules` 不改现值，显式 `{}` 清空规则。模型基础价格及扩展倍率沿用原有持久化格式；锁定行与目录同步仍由现有价格发布链路处理。

| 链路 | 实现入口与行为 |
| --- | --- |
| 手工配置、批量配置、目录预览／发布 | `model.PriceRateRules` 严格解码，`ValidatePrice`／持久化校验，完整版本发布 |
| 普通 HTTP 与 SSE | `RelayHandler → AttemptQuota → Quota.EvaluateProviderUsage`，最终使用 provider usage |
| Claude 原生与 Chat 转换 | `ClaudeUsageMerge → ClaudeUsageToOpenaiUsage` 同时传递实际 Speed 和独立冲突标记 |
| Responses WebSocket | 每个 Attempt 的开始时间；usage 克隆、合并、最终快照保留速度证据 |
| Realtime 与转写 | 每个独立操作创建 Attempt；`UsageEvent` 克隆、合并和 `ToChatUsage` 保留速度事实 |
| 按次／独立工具与独立用量 | 保留各自既有计算；不把条件倍率乘到 owner 总金额上 |
| 管理员试算 | `POST /api/prices/preview`，运行相同规则解析、证据检查与 token reducer；不访问余额或提交上游 |
| 费用展示 | `token_billing` 保存已含条件倍率的加权单位和各项倍率；`effective_extra_ratios` 保存扩展项有效单价，前端不能再乘一次规则 |

试算使用草稿 `price`、`facts`、`usage`、可选 `extra_tokens` 和 `group_ratio`。`usage.prompt_tokens` 是完整输入长度，`facts.started_at` 是含时区的 RFC3339 时间。UI 默认组倍率 1，提供完整输入、输出、缓存读取和两种 TTL 数量，并可添加其他注册的 Token 计量项。模拟证据只存在于该请求的计算中，不授予真实计费权限。

## 验证覆盖

| 顺序 | 工作 | 必须验证 |
| --- | --- | --- |
| 1 | 共享倍率解析与有效价格结果 | 覆盖优先级、0 与省略、跨组相乘、不重复计费 |
| 2 | Speed 证据贯穿适配器和公共 usage | 非流式、流式合并、冲突、请求 fast 但实际 standard；未知字段透传 |
| 3 | 有限条件匹配、时间事实与试算 | 第一条命中、未知／缺失区别、阈值两侧、跨午夜、周末与夏令时 |
| 4 | 管理界面和诊断 | 继承显示不写覆盖、排序可访问性、日志与计算一致 |
| 5 | 配置和目录发布 | 新版往返、锁定保留、省略／清空、版本发布，拒绝旧规则字段 |

还需覆盖条件独立缓存倍率改变证据要求、其他独立组件仍可收费、原按次／工具费用不受影响，以及 provider work 后缺失证据不会触发重试。验收以可观察收费结果和真实持久化契约为准，不以代码分支覆盖率代替。

## 复杂度取舍

选择有限条件规则，是因为实际需求已经包含多条件组合和缓存覆盖；继续新增专用布尔开关会复制同一规则。没有选择 new-api 式自由表达式，是因为当前目标只需要调整倍率，不需要让管理员重写用量拆分和整笔费用公式。

第一版不引入节假日日历、按执行时长拆分峰谷、分段累进收费、用户自定义公式、任意属性提取或跨模型全局折扣层。只有出现无法通过现有条件和倍率表达的实际收费契约时，再扩展对应边界。
