# 条件倍率配置

## 文档状态

状态：当前实现。

在模型价格编辑框中设置条件规则，使用“试算当前价格草稿”检查结果。服务档位和速度分别标注 `service_tier`、`speed` 字段；展开“时间折扣”面板后设置该组共用的时区及时间规则。价格表操作见 [价格更新](./prices_update.md)；开发契约见 [条件倍率规则设计](../dev/pricing-rate-rules.md)。本文示例数字只解释配置语义，不是官方价目。

## 先记住三件事

1. **统一倍率只填一次。** 夜间全部半价，填写 `all = 0.5` 即可。
2. **局部配置覆盖统一倍率。** 缓存读取填 `1`，表示该规则不调整缓存读取价格。
3. **只有时间折扣需要优先级。** 档位、速度和长度区间互不重叠，不同维度倍率相乘。

统一倍率属于当前模型的一条规则，不会自动影响其他模型。第一版影响输入、输出及现有 token 调整链路支持的缓存等扩展项；按次价格、独立工具调用和其他独立用量费用保持原有计价。

## 统一倍率与局部覆盖

编辑界面默认显示一个输入框：

```text
时间：23:00 至 07:00
时区：Asia/Shanghai

统一倍率：[0.5]

▸ 自定义部分计价项
```

展开后可设置例外：

```text
输入             跟随统一倍率：0.5
输出             跟随统一倍率：0.5
缓存读取         自定义：[1]
缓存写入 5m      跟随输入：0.5
缓存写入 1h      跟随输入：0.5
```

| 填写方式 | 含义 |
| --- | --- |
| 不填写／选择跟随 | 使用上一级倍率 |
| `1` | 本条规则不调整这一项 |
| `0.5` | 本条规则将这一项打五折 |
| `0` | 本条规则将这一项设为免费 |

继承顺序是：**计量项自定义 → 输入／输出 → 统一倍率 → 1**。在一条规则里只选一个倍率，不会把这几级重复相乘。

| 示例 | 输入 | 输出 | 缓存读取 |
| --- | ---: | ---: | ---: |
| 统一 0.5 | 0.5 | 0.5 | 0.5 |
| 统一 0.5，输入 0.8 | 0.8 | 0.5 | 0.8 |
| 统一 0.5，输出 0.8 | 0.5 | 0.8 | 0.5 |
| 统一 0.5，缓存读取 1 | 0.5 | 0.5 | 1 |

原有 `extra_ratios` 定义缓存等计量项的基础相对价格；规则里的 `extra_multipliers` 在此基础上调整价格。若缓存基础价格已经是输入的十分之一，缓存调整倍率填 `1` 会保留这个基础价格，不会把缓存改成普通输入价。

## 选择条件

| 配置区域 | 允许配置的条件 | 是否需要排序 |
| --- | --- | --- |
| 服务档位 | 实际服务档位，如 Flex、Priority | 不需要；同一取值不能重复配置 |
| 速度 | 实际速度，如 Fast、Standard | 不需要；同一取值不能重复配置 |
| 长上下文 | 输入长度区间，可选“适用速度” | 不需要；同一速度的长度区间不能重叠 |
| 时间折扣 | 星期、每日时段、该时间组的时区 | 需要处理重叠优惠时，调整优先级 |

规则不需要名称，界面自动显示条件摘要，例如 `flex`、`输入 > 200000 Token` 或 `周六 / 周日 · 23:00–07:00`。

只有时间折扣显示“提高／降低优先级”。优先级高的规则先匹配，第一条命中后停止。例如周末夜间优惠应放在普通夜间和周末优惠之前。

多个维度的倍率仍然相乘。例如速度组 Fast 为 2，时间组夜间为 0.5，最终倍率为 1。某条规则的局部倍率填 1，只取消该规则对该项的调整，不会取消其他维度的倍率。

## 常见配置

### 夜间半价

在时间折扣组添加：时间 `23:00 → 07:00`，统一倍率 `0.5`，明确选择时区。

其他时段不命中规则，按原基础价格计算。如果需要峰时加价，再添加对应时段和统一倍率。

### 周末八折，周末夜间四折

按下面的优先级排列时间规则：

| 顺序 | 条件 | 统一倍率 |
| --- | --- | ---: |
| 1 | 周六／周日，且 23:00～07:00 | 0.4 |
| 2 | 每天 23:00～07:00 | 0.5 |
| 3 | 周六／周日 | 0.8 |

| 操作开始时间 | 命中规则 | 倍率 |
| --- | --- | ---: |
| 周五 23:30 | 夜间 | 0.5 |
| 周六 00:30 | 周末夜间 | 0.4 |
| 周六 07:00 | 周末 | 0.8 |
| 周一 12:00 | 无 | 1 |

星期按操作开始时的当地日期判断。所有时间区间包含开始、不包含结束。23:00～07:00 支持跨午夜；需要全天时省略时间条件。

### 夜间半价，缓存读取保持原价

下面展示单条规则的倍率部分：

```json
{
  "all": 0.5,
  "extra_multipliers": {
    "cache_read_input_tokens": 1
  }
}
```

`cache_read_input_tokens` 是 Claude 缓存读取 key；OpenAI 缓存命中用 `cached_tokens`，两者独立。其他协议可能使用不同 key，应在配置项列表中选择对应项，不自行猜测字段别名。

### 长上下文涨价，但缓存不涨价

配置条件：完整输入超过阈值；输入倍率 2、输出倍率 1.5，缓存读取独立倍率 1。

假设基础输入为 $3／百万 token，基础缓存读取为 $0.3／百万 token：命中后普通输入为 $6，缓存仍为 $0.3。再命中夜间统一五折时，分别为 $3 和 $0.15。

阈值看的是包含缓存的完整输入长度，不是扣除缓存后的普通输入数量；命中后整次操作使用该档价格，不是只对超过阈值的部分加价。

### Fast 不叠加长上下文

在长上下文规则中同时配置“实际速度为 Standard”和“完整输入超过阈值”。Fast 操作不会命中该条规则。

价格按上游实际执行结果选择。客户端请求 Fast，上游实际返回 Standard 时，应按 Standard 匹配；请求头或客户端选项不能保证最终使用 Fast。

## 新版 JSON 示例

下面是一个完整的 `rate_rules` 值，表达夜间半价、缓存读取不打折。可在模型价格配置中使用。

```json
{
  "version": 2,
  "schedule": {
    "timezone": "Asia/Shanghai",
    "rules": [
      {
        "id": "night",
        "when": {
          "time": {
            "start": "23:00",
            "end": "07:00"
          }
        },
        "multipliers": {
          "all": 0.5,
          "extra_multipliers": {
            "cache_read_input_tokens": 1
          }
        }
      }
    ]
  }
}
```

规则组可省略。完整字段与多组示例见 [开发设计](../dev/pricing-rate-rules.md#完整配置示例)。

## 配置前后怎样核对

编辑框提供与正式计算共用的后端试算功能。填入实际速度／档位、完整输入和缓存用量、操作开始时间后，核对：

- 命中了哪些条件，时间折扣是否被更高优先级的规则覆盖。
- 每项显示的是跟随值还是自定义值。
- 各项基础价、最终倍率、有效单价和金额。
- 与同一价格发布和事实下的真实消费记录是否一致。

特别检查阈值前后、周末边界、跨午夜，以及缓存倍率为 0 或 1 的情况。试算输入只是模拟事实，不能替代真实上游计费证据。

## 需要知道的限制

- **时间固定，价格不一定固定。** 操作跨过峰谷边界不会仅因此换档；管理员在执行期间更新价目、规则或时区，结算仍可能使用更新后的当前完整价格发布。
- **长连接按操作判断。** 每次独立计费操作有自己的开始时间，不沿用整个连接建立时间。
- **缺失证据不是默认档位。** 无法确定且可能影响金额时，系统按现有组件规则处理并记录诊断，不猜测一个更便宜或更贵的价格。
- **第一版按每天／每周重复。** 暂不提供节假日日历、自由公式或按执行时长拆分峰谷。
- **使用新版配置。** 旧固定规则未上线，不提供迁移兼容；配置接受新版 v2 或 `{}` 清空，省略字段则保留已有规则。
